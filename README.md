### Projecte 02 🔌 — Consultoria EverPia
🔗 [github.com/batallaa/Projecte2](https://github.com/batallaa/Projecte2)

- **Repte inicial:** EverPia rebia encàrrecs de clients i nosaltres, com a júniors, havíem de resoldre tasques reals: seleccionar un SAI adequat, recuperar accés a sistemes i assessorar sobre hosting i domini.
- **Solució proposada:** Anàlisi comparativa de SAIs per potència i autonomia, procediment de recuperació de credencials i informe d'elecció de hosting adaptat al client.
- **Passos seguits:** Calcular consum dels equips → convertir a VA → filtrar models amb marge de seguretat → documentar la recomanació al repositori.
- **Evidències generades:** Kanban del projecte, repositori GitHub documentat i presentació d'elecció de hosting al client.
- **Decisions tècniques:** Comparativa de serveis d'hosting reals de mercat justificant la tria per pressupost i requisits del client.
- **Dificultats:** No quedava clar com calcular la potència necessària del SAI ni com comparar models amb especificacions molt diferents.
- **Solució aplicada:** Estructurar el procés en passos: calcular consum total, convertir a VA i filtrar models que el superin amb un marge de seguretat.
- **Aprenentatge:** Treballar en IT no és només tècnica — cal justificar les decisions davant d'un client i adaptar-se al seu pressupost. Primera vegada treballant amb un Kanban real.

### Projecte 03 🌐 — Consultoria EverPia 2: "Sobreviure en una empresa IT"
🔗 [github.com/batallaa/Projecte-3](https://github.com/batallaa/Projecte-3)

- **Repte inicial:** EverPia creixia i rebia més clients dels que podia gestionar. Com a júniors havíem d'assumir tasques cada vegada més complexes: gestió de contrasenyes, discos LVM, LDAP i configuració d'un servidor DNS.
- **Solució proposada:** Implementació d'un gestor de contrasenyes corporatiu, configuració de volums lògics amb LVM, introducció a directoris LDAP i desplegament complet d'un servidor DNS.
- **Passos seguits:** Instal·lar i configurar el gestor → implementar LVM → estudiar LDAP → configurar zona directa DNS → verificar amb `dig` i `nslookup` → configurar zona inversa.
- **Evidències generades:** Kanban, repositori complet, rèplica web, configuració DNS documentada, comparativa LVM vs Espais d'Emmagatzematge i vídeo explicatiu del DNS.
- **Decisions tècniques:** Treball incremental al DNS per evitar errors en cadena; documentació de cada pas per facilitar la revisió posterior.
- **Dificultats:** Els fitxers de zona del DNS tenen una sintaxi molt estricta — un punt mal posat fa fallar tot el servei.
- **Solució aplicada:** Configurar primer la zona directa, verificar-la amb `dig` i `nslookup`, i només llavors afrontar la zona inversa.
- **Aprenentatge:** La documentació no és opcional. Sense ella, és impossible tornar enrere quan alguna cosa falla.

### Projecte 04 💼 — Consultoria EverPia 3: La carta de presentació professional
🔗 [github.com/batallaa/Projecte-04](https://github.com/batallaa/Projecte-04)

- **Repte inicial:** Tancament de la trilogia EverPia amb el projecte més exigent del curs: 168 commits i 15 tasques que cobreixen DRP, accés remot, auditoria de servidors, NFS, CUPS i disseny d'e-commerce amb Figma.
- **Solució proposada:** Política de backups i imatges del sistema, configuració d'SSH, RDP i assistència remota, auditoria de qualitat de servidors i maqueta d'e-commerce dissenyada a Figma.
- **Passos seguits:** Estudi del cas DRP → implementació de backups → configuració accés remot → auditoria del servidor → disseny landing page i checkout a Figma.
- **Evidències generades:** Treball col·laboratiu via forks i pull requests a GitHub, presentació de maqueta al client i Kanban del projecte.
- **Decisions tècniques:** Separació clara entre SSH (Linux) i RDP (Windows) segons el sistema destí; ús de Figma per validar el disseny amb el client abans d'implementar.
- **Dificultats:** SSH estava actiu però no era accessible des d'una màquina externa per culpa del firewall.
- **Solució aplicada:** Obrir el port 22 a `ufw` i verificar que el servei escoltava a la interfície correcta. El diagnòstic sistemàtic — estat del servei, `telnet`, logs — va ser l'aprenentatge real.
- **Aprenentatge:** En una empresa IT cal ser versàtil: passar d'una tasca de sistema (NFS, CUPS) a una creativa (Figma, e-commerce) dins del mateix projecte.

### Projecte 05 🌱 — La Incubadora
🔗 [github.com/batallaa/projecte5-batallaa](https://github.com/batallaa/projecte5-batallaa)

- **Repte inicial:** Deixar de ser treballadors d'EverPia per convertir-nos en emprenedors. Durant 4 setmanes la classe va ser una incubadora: calia dissenyar una empresa IT real amb problema real, client, solució, model de negoci i números defensables davant d'un jurat inversor.
- **Solució proposada:** Empresa IT dissenyada des de zero amb proposta de valor diferencial, arquitectura tècnica amb Windows Server 2025 i Active Directory, plataforma Moodle i pla de sostenibilitat Green IT.
- **Passos seguits:** Definir la idea → investigar el mercat → dissenyar la solució tècnica → instal·lar Windows Server 2025 → configurar el domini → desplegar Moodle → preparar la presentació.
- **Evidències generades:** Control de versions documentat via GitHub Classroom, informe de llicenciament de Windows Server 2025 i presentació de l'empresa amb visió Green IT.
- **Decisions tècniques:** Tria de Windows Server 2025 com a base del domini; Moodle com a plataforma formativa de l'empresa.
- **Dificultats:** En promoure el servidor a controlador de domini, el DNS es va sobreescriure i es va perdre la connectivitat externa.
- **Solució aplicada:** Configurar correctament els reenviadors DNS perquè els clients poguessin continuar resolent dominis externs mantenint el servidor com a DNS intern.
- **Aprenentatge:** Primera vegada connectant la part tècnica amb la de negoci. No n'hi ha prou amb saber instal·lar: cal saber per què, quant costa i quina necessitat resol.

### Projecte 06 🦐 — Nexus: Infraestructura segura per a e-learning
🔗 [github.com/batallaa/projecte6-batallaa](https://github.com/batallaa/projecte6-batallaa)

- **Repte inicial:** El client Nexus volia una plataforma e-learning per a tècnics informàtics sobre una infraestructura eficient, sostenible i amb costos controlats. Treball en equip amb Nezar Mghari i David Ballesteros.
- **Solució proposada:** Desplegament i comparativa Apache vs Nginx, implementació de PKI amb certificats digitals, monitoratge de sistemes i comparativa Moodle vs Canvas LMS amb recomanació final argumentada.
- **Passos seguits:** Estudiar el funcionament d'Internet → desplegar Apache → desplegar Nginx → comparar rendiments → implementar PKI → desplegar Moodle i Canvas → elaborar memòria tècnica.
- **Evidències generades:** Memòria tècnica completa, presentació al client Nexus i repositori estructurat amb tota la documentació.
- **Decisions tècniques:** Recomanació de Nginx per al client per la seva arquitectura lleugera; CA interna per a la PKI corporativa.
- **Dificultats:** Els navegadors no confiaven en el certificat SSL perquè estava signat per una CA interna no reconeguda públicament.
- **Solució aplicada:** Importar el certificat de la CA manualment al navegador i documentar el procés, entenent la diferència amb autoritats reconegudes com Let's Encrypt.
- **Aprenentatge:** En IT rarament hi ha una resposta única correcta. Tot depèn del context, del client i dels recursos disponibles.

### Projecte 07 🍉 — FoodLogístic S.A.: Modernització logística
🔗 [github.com/batallaa/projecte-7-batallaa](https://github.com/batallaa/projecte-7-batallaa)

- **Repte inicial:** FoodLogístic S.A. — empresa de distribució alimentària a Mataró, 35 treballadors i 25M€ de facturació — necessitava alta disponibilitat de fitxers i impressió, migració del correu al núvol, web corporativa legal i formació en LOPD. Treball en parella amb Pol Castaño.
- **Solució proposada:** Servidors de fitxers i impressió en alta disponibilitat, migració a Microsoft 365, web corporativa compliant i vídeo formatiu LOPD per als empleats, amb pressupost i Gantt detallats.
- **Passos seguits:** Analitzar el sector → dissenyar la web → configurar servidors en HA → crear vídeo LOPD → avaluar Microsoft 365 vs Google Workspace → elaborar pressupost i Gantt.
- **Evidències generades:** Memòria tècnica de la proposta, web corporativa de FoodLogístic S.A. i repositori personal documentat.
- **Decisions tècniques:** Tria de Microsoft 365 per la millor integració amb l'entorn Windows existent; arquitectura amb dos nodes sincronitzats per a l'alta disponibilitat.
- **Dificultats:** Alta disponibilitat no significa tenir un backup — significa un sistema que commuta automàticament sense intervenció manual.
- **Solució aplicada:** Replantajar l'arquitectura amb dos nodes sincronitzats en lloc d'un servidor únic amb còpies programades.
- **Aprenentatge:** Fer un pressupost i una estimació temporal és tan important com saber configurar un servidor. Sense números, un client no pot prendre decisions.

- **Solució proposada:** Anàlisi de la situació digital actual del negoci i pla de digitalització concret adaptat a la seva realitat, pressupost i objectius.

- **Evidències generades:** Anàlisi de la situació digital (Tasca 01) i proposta de pla de digitalització (Tasca 02), tots dos documentats al repositori.

## 4. 🗂️ Metodologia de Treball

### Com es divideix un projecte en tasques

Cada projecte s'estructura en **fases clarament diferenciades:**

```
📌 FASES D'UN PROJECTE
├── 1. Anàlisi       → Entendre el problema i els requeriments
├── 2. Planificació  → Definir tasques, temps i recursos
├── 3. Desenvolupament → Executar les tasques planificades
├── 4. Proves        → Verificar que la solució funciona
├── 5. Documentació  → Registrar tot el procés i les decisions
└── 6. Entrega       → Lliurament final i presentació
```

---

### Tauler Kanban

Les tasques s'organitzen en un tauler amb 4 columnes:

| 📋 Pendent | 🔄 En curs | 🔍 En revisió | ✅ Finalitzat |
|-----------|-----------|--------------|--------------|
| Tasques per fer | Tasques actives | Tasques acabades pendent de revisió | Tasques tancades |

[Kanban](https://planner.cloud.microsoft/webui/v1/plan/Rj_oSd91tUm7bY0AK7yVaJYAEl7I?tid=c7b5981a-7820-4ac8-ae65-03515ea81317)

---

### Diagrama de Gantt

El Gantt permet visualitzar:
- La **durada** de cada tasca
- Les **dependències** entre tasques (quines cal acabar primer)
- Els **terminis** i dates d'entrega
- Les **desviacions** respecte a la planificació inicial

![Gantt](/img/gantt.png)

---

### GitHub com a eina de seguiment

GitHub ha estat la eina central per documentar el procés:

- **Repositoris:** Un per projecte, amb estructura clara de carpetes
- **README.md:** Documentació principal de cada projecte
- **Commits:** Evidència cronològica del progrés i les decisions
- **Branques:** Separació entre versions o fases del projecte
- **Issues:** Registre de problemes detectats i resolts
